3Architecture in one sentence

agentassist

The chat endpoint runs four rate-limit tiers + a per-tenant 24-hour token budget + a concurrent-stream cap + an origin allowlist + server-side PII redaction, hands an HMAC-signed visitor session to agent.iter_turn, which streams Claude's response over SSE with optional retrieval and optional OpenTelemetry, and Anthropic itself enforces the per-tenant web_fetch host allowlist on the tool-execution side.

virtuele-assistent

A Kotlin/Ktor backend authenticated via X-API-Key from nginx runs a real RAG loop (Qdrant collections populated by Airflow-scheduled scrapers, hybrid semantic+BM25 retrieval, optional HyDE, cross-encoder reranking) and streams the assistant's response to a Next.js chat frontend, while a Next.js admin frontend backed by Postgres lets editors manage prompts and watch BSAT scores in Langfuse.

5Where each one is genuinely stronger

agentassist wins on

  • Cost ceiling per tenant (24h token budget, enforced server-side)
  • Visitor session security (HMAC + tenant-bound + Secure;HttpOnly;SameSite cookies)
  • Default security headers (CSP, X-Frame, Permissions-Policy, Referrer)
  • Per-tenant admin passwords with role-based tokens
  • Live-information access (Anthropic-enforced web_fetch allowlist)
  • Iteration speed (tests run in ~3 seconds with no external services)
  • Distribution (clone-to-running in under a minute)

virtuele-assistent wins on

  • Knowledge base scale (real RAG with hybrid + HyDE + reranker)
  • Scheduled, idempotent ingestion (Airflow per tenant)
  • Tenant isolation at retrieval layer (per-tenant Qdrant collection is harder to bypass than a directory)
  • Product-owner observability (Langfuse traces, BSAT, topic analytics)
  • Editor workflow depth (prompt-variables wizard with ~20 fields)
  • Edit-message + branch navigation (implemented)
  • Embeddable widget bundle (shipped)

7Decision rule

A simple two-question test.

QuestionIf yesIf no
Tenant knowledge fits in a single Markdown file (under ~50 KB), maybe supplemented by one public website?agentassistcontinue
You have an editorial team that needs BSAT scoring, full prompt-variables wizard, and scheduled scraping per tenant?virtuele-assistentagentassist (with the optional retrieval extension point if you grow into it)

For the original Montferland use case (one public website, modest content, single editor team), both work. agentassist runs at near-zero idle cost; virtuele-assistent has more polish at the editorial workflow layer.

Bottom line. agentassist is the right choice for most public-facing chatbot deployments today: one container, no external services, full security posture, drop-in deployable, and OSS-ready. virtuele-assistent earns its complexity only when the knowledge base genuinely needs real RAG (thousands of pages, frequent updates, scheduled scraping) or when editor analytics are a hard requirement. The two are not in opposition; agentassist is the lightweight default, virtuele-assistent is the heavy specialist.
