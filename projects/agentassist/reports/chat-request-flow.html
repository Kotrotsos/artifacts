Chat request flow

How a single message travels from the browser through the multi-tenant chatbot and back.

1Main path: one chat turn

Solid arrows are calls. Dashed arrows are streaming responses. Boxes inside a lane are work that stays in that component.

  1. User submits. Frontend captures Enter and calls fetch("/api/{tenant}/chat").
  2. POST to Flask. Body is { message, session_key }. Session key is browser-issued and stored in sessionStorage.
  3. Validate and redact. Flask rejects unknown tenants, oversized bodies (over 64 KB), and rate-limited IPs. pii.py redacts BSN, IBAN, email, phone, postcode, doc-numbers before the message reaches the model or logs.
  4. Hand off to agent. agent.iter_turn(...) is called as a regular Python generator.
  5. Prepare the turn. Agent acquires a non-blocking per-session lock (two concurrent turns on the same key are rejected, not serialized), builds the system prompt with the tenant's context.md and tone-of-voice, and declares a web_fetch tool capped to the tenant's allowed_domains and max_uses=3.
  6. Call Anthropic. client.messages.stream(model, system, tools, messages). Wrapped in a retry loop (up to 2 attempts) for transient errors.
  7. Anthropic generates. Streams text token by token, may invoke web_fetch server-side (the model never gets host-side credentials; the fetch runs on Anthropic infrastructure and is forced to respect the allowlist).
  8. Stream back. The SDK yields content_block_delta events (text_delta) and content_block_start events (server_tool_use).
  9. Agent reshapes events. Each SDK event becomes a small dict: { type: "text" | "status" | "sources" | "retry" | "error" | "done" }.
  10. SSE to browser. Flask wraps each dict as a Server-Sent-Events frame. X-Accel-Buffering: no + Railway's edge config keep the stream unbuffered.
  11. Render incrementally. Frontend appends text deltas to the current bot bubble, shows a single live activity row for tool calls (aggregated, no stacking), and adds clickable source chips when a sources event arrives.
  12. Loop. Steps 8 to 11 repeat for every event. A tool call mid-stream finalizes the current text bubble and opens a new one once text resumes.
  13. On done. Agent commits the full turn to in-memory history, extracts source URLs from web_fetch_tool_result blocks, and emits the final sources + done events. Frontend attaches the Copy / Regenerate action bar to the last bubble.

2Sub-flow: server-side web_fetch

When the model decides it needs current information, it calls the declared web_fetch tool. The fetch runs on Anthropic's side, not on your server, and the host allowlist is enforced there.

Why this matters: prompt injection in a user message cannot redirect web_fetch to an attacker-controlled host. The allowlist is enforced by Anthropic, not by Claude.

3Retry behavior on transient errors

529 overload, 5xx, 429, and connection errors are retried up to two times with 1.5s then 3s backoff. The frontend gets an explicit retry event so it can clear partial output.

4Files involved

app.py Flask routes, validation, rate-limit middleware, SSE wrapping. agent.py Tenant-aware streaming, retry, source extraction, history. tenants.py Tenant dataclass + filesystem store. Source of truth for context.md and config.json. pii.py Dutch PII redaction (BSN with elfproef, IBAN, email, phone, postcode, doc-number). ratelimit.py Sliding-window rate limiter, in-memory. auth.py HMAC-signed admin tokens (no JWT dependency). static/index.html Full-screen + bubble chat UI, SSE consumer, a11y, activity aggregation. static/admin.html Tenant config + context editor. tenants/{id}/ Per-tenant config.json and context.md.
