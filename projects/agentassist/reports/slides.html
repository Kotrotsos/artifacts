02 / what we built

From bubble to platform, six iterations

  • Day 1. Single-tenant Flask + Anthropic chat bubble. One file, one tenant, no admin.
  • Iteration. Switched to managed agents, then back to Messages API for real token-level streaming.
  • Multi-tenant refactor. Six tenants, filesystem store, admin UI, PII redaction, rate limit, web_fetch allowlist.
  • Security pass. Codex review, abuse controls, server-issued HMAC sessions, CSP, per-tenant token budget.
  • Polish. OpenTelemetry hook, draft/publish flow, prompt preview, per-message feedback, retrieval extension.
  • OSS prep. LICENSE, README, SECURITY, CONTRIBUTING, CHANGELOG, GitHub Actions, docker-compose.

05 / the chat path

Public endpoint, anonymous by design, bounded by layers

  • Four rate-limit tiers. Per IP per minute, per IP per hour, per session per minute, per tenant per minute.
  • Per-tenant 24h token budget. JSONL ledger. 503 with Retry-After once the daily ceiling is hit.
  • Concurrent stream cap. 2 per IP, 20 per tenant by default.
  • Origin pinning per tenant. Allowlist enforced server-side.
  • Server-issued HMAC sessions. Tenant-bound, Secure HttpOnly SameSite cookie, ignored if client supplies its own.
  • Server-side PII redaction. Dutch patterns (BSN with elfproef, IBAN, email, phone, postcode, paspoort, rijbewijs). Runs before model and logs.
  • web_fetch host allowlist. Enforced by Anthropic on tool execution. Prompt injection cannot redirect the fetch.

06 / the admin

Real editor product, not a single form

Built in

  • Super-admin and per-tenant editor roles (argon2-hashed passwords)
  • Sidebar tenant list with DRAFT badges
  • Six tabs: Overzicht, Inhoud, Variabelen, Kennis, Beveiliging, Feedback
  • Draft / publish / discard flow
  • Prompt-preview dialog
  • Live thumbs-up/down feed
  • Stats cards (24h tokens, 7d feedback, draft state)

What editors get

  • Save a change, preview the assembled system prompt, then publish.
  • Token-budget remaining at a glance.
  • Visitor feedback (rating + comment + excerpt) for the last 100 messages.
  • Dark mode. Toast confirmations. Mobile-responsive.

07 / why this shape wins

The shape of the system is the win

  • Fails closed on missing configuration. No env var, no boot. No silent default secret.
  • One language stack. Python on the server, vanilla HTML/JS in the browser. New contributor reads it all in an afternoon.
  • No database to migrate. Tenant config + context + ledgers are files. git diff is your change log.
  • Tests run with zero external services. 123 cases, ~3 seconds, no mocks of Postgres, no test containers.
  • Cost ceiling per tenant, enforced server-side. One bad day from one tenant cannot blow up your Anthropic bill.
  • Provider abstraction. Anthropic by default. Subclass Provider.messages_stream() for OpenAI, Azure, local model.

09 / why this works for OSS

Different criteria than enterprise

What OSS evaluators check

  • Can I clone and run in 5 minutes?
  • How many secrets do I need?
  • Can I read all the code in one sitting?
  • Are there customer artifacts I have to clean up?
  • Does it host on free tiers?
  • Can I swap the vendor?

What agentassist answers

  • Yes, under a minute.
  • One: ANTHROPIC_API_KEY.
  • ~2,300 LOC of hand-written code.
  • None.
  • Yes.
  • Yes, Provider interface ships with the default.

A heavyweight stack can be technically excellent and still fail the OSS test, because the worst-case operator drops the project on a host without reading the docs. Small surface, fail-closed defaults, no external services, one language. That is the shape that travels.

10 / the decision rule

Two questions, one answer

Question one

Does your tenant's knowledge fit in a single Markdown file plus maybe one public website?

Yes → agentassist.

Question two

Do you genuinely need real RAG with scheduled scraping plus editor-facing BSAT analytics?

Yes → heavyweight specialist. No → agentassist with the optional retrieval extension when you grow.
