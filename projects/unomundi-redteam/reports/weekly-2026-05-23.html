F-10 MED — Public child account restoration endpoint

https://restore.unomundi.com serves a static HTML/JS page titled "Restore account" with an email + 6-digit OTP form ("Enter your email and verify OTP to reactivate the account before permanent deletion"). The accompanying app.js calls both https://supabase.unomundi.com and https://dev-supabase.unomundi.com. This is the user-facing surface for un-deleting a child / guardian account during the GDPR-mandated retention grace period. Issues to assess:

  • Rate limiting on the OTP flow (not assessed — would require actual submission)
  • OTP entropy and reuse window (not assessed)
  • Why the page calls dev-supabase as well as prod
  • Whether the restore action is logged in guardian_action_logs (currently 0 rows)

The service_role JWT from F-5 has full read access. Currently empty; flagged for next-week monitoring.

F-12 LOW (information) — ElevenLabs "Una" voice agent for children

The product integrates ElevenLabs for a conversational voice agent ("Una"). The API exposes endpoints to create sessions, log lifecycle events, consume metered minutes, and receive webhooks (/webhooks/una/*) for safety events and conversation summaries. Notes:

  • Children ages 6-12 are the speakers; voice data flows through ElevenLabs as a sub-processor (GDPR Art.28 DPA required, NL DPA notification for children's voice data is a real obligation here).
  • Two webhook routes have an empty security: block in the OpenAPI spec. They likely use HMAC signature validation in headers (common pattern that doesn't surface in OpenAPI), but the spec doesn't say so. POST tests not performed (would create lifecycle artifacts).
  • The guardian_action_logs table is 0 rows on prod, suggesting safety event flow is not yet wired or no flagged events have occurred.

Remediation order (priority)

  1. Close the leak path first, then rotate. Remove public reachability of /api/platform/projects/default/settings on supabase.unomundi.com entirely (VPN, IP allowlist, or SSO). Then rotate the JWT secret again and pick a TTL of months not decades. Without step one, rotation is theater.
  2. Eliminate public reach of supabase.unomundi.com Studio + platform endpoints. Self-hosted Supabase Studio is not designed to be internet-facing.
  3. Wrap /rest/v1/ on dev-supabase too. Basic Auth currently stops at the Studio / platform API; PostgREST schema disclosure is still anonymous.
  4. Repoint admin.unomundi.com at a real prod Supabase project. Current production admin work is happening on a dev backend that has a different JWT secret, no rate limits documented, and a known anonymous schema disclosure surface.
  5. Take down or auth-wrap dev-api.unomundi.com/docs. The route was removed on prod for a reason; the dev mirror undoes that fix.
  6. Take down or auth-wrap dev-admin.unomundi.com. The bundle there is more damaging than admin's (leaks internal Kong IP in cleartext HTTP).
  7. Audit restore.unomundi.com: OTP entropy, replay window, rate limits, why it calls dev-supabase, and whether the restoration action emits a guardian_action_logs row.
  8. Database + Storage log review for the period since the previous JWT secret was active (2026-03-03 onward). The fact that prod has only 1 explorer profile + 3 profiles + 2 guardian settings makes log review tractable — confirm no unexpected sessions used the prior service_role JWT.
  9. GDPR-K Article 33 clock: 72-hour notification to the Dutch DPA (AP) is mandatory if logs show any unauthorized access to children's PII while the prior or current service_role JWT was in the wild. The legal basis is unambiguous — under-13 PII triggers the children's-data heightened standard.
