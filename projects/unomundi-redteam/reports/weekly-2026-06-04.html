The one thing that still matters most

The endpoint that leaked the service_role JWT (god-mode on the production children's database) was removed, so the secret can no longer be harvested. But the secret was not rotated. The JWT that was publicly exposed for weeks is still valid against production right now, verified this scan, and it does not expire until 2036. Closing the leak without rotating is half a fix: anyone who saved that token during its exposure window still has full, RLS-bypassing access to every table, GoTrue admin, and Storage.

Action: rotate the JWT secret and reissue the anon + service_role tokens with a short TTL, today. Until then, treat the production database as compromised-pending-rotation.

03Critical residual

C-1Leaked service_role credential closed at the source but never rotatedCritical

What changed

Last week, GET https://supabase.unomundi.com/api/platform/projects/default/settings returned 200 and leaked the JWT secret plus a ready-to-use service_role token. This week that endpoint, and the whole Studio / platform surface, returns 404. Good: the secret can no longer be pulled from the public internet.

Why it is still critical

The token that was exposed (minted 2026-05-15, expiry 2036) was reachable by anyone for the entire period it was public. Removing the page does not invalidate copies already taken. This scan confirmed the exposed token still authenticates against production:

HEAD https://supabase.unomundi.com/auth/v1/admin/users
     apikey + Authorization: Bearer <previously-leaked service_role JWT>
=> 405 Method Not Allowed     (GoTrue accepted the token; 401/403 would mean rotated)
   (probe used HEAD, page=999999, discarded body — no user data retrieved)

That token bypasses Row Level Security on all 60 tables (including explorer_profiles, guardian_*, consent_records, legal_consent_archive), and unlocks GoTrue admin and Storage. The production data plane /rest/v1/ is also reachable, so the token is directly usable.

Fix

  1. Rotate the JWT secret in the Supabase config and reissue the anon and service_role JWTs. Set a sane TTL (1 year, not 10).
  2. Roll the new anon key into the prod admin SPA, the app, and any server config; roll new service_role into backend services only.
  3. Review DB, Storage and GoTrue audit logs for service_role use from the original mint (2026-03-03) through rotation. If logs show access to children's PII you did not perform, the GDPR-K Art.33 72-hour clock starts.

04Still open

N-1 / F-1bPostgREST data plane and full schema reachable unauthenticated (prod and dev)High

Evidence

GET https://supabase.unomundi.com/rest/v1/       => 200, 292,834 bytes, 60 tables (no apikey)
GET https://dev-supabase.unomundi.com/rest/v1/   => 200, 292,557 bytes, 60 tables (no apikey)
dev-supabase Studio UI still behind Basic Auth ("Restricted Studio"), but /rest/v1/ is not.

The OpenAPI schema names every table and column, including the child-data and consent tables. Schema grew from 283KB to 292KB since last week, with new compliance/audit tables now in the model: legal_consent_archive, guardian_action_logs, explorer_settings, user_subscription_lifecycle_v. This raises, not lowers, the value of the still-valid token in C-1.

Fix

Put /rest/v1/ behind auth/network controls on both hosts (require apikey at the edge, and confirm RLS denies anon on every table; place dev behind VPN/IP allowlist). Schema introspection should not be anonymous.

F-9dev-api.unomundi.com/docs exposes the full API specHigh

GET https://dev-api.unomundi.com/docs => 200 (Scalar OpenAPI, ~47KB), documenting the AI session, billing, content-import, privacy-export, video playback-token and Una webhook routes. Prod /docs is correctly 404; the dev mirror still leaks the same route map. Take it down or auth-gate it.

F-14Open signup on production authHigh

GET /auth/v1/settings => disable_signup: false. Anyone can self-register against the production auth server. Combined with the historical client-settable user_metadata.role (F-13, not re-tested this week to avoid user enumeration), this is a path to probe RLS as a self-issued identity. Disable open signup unless it is a product requirement, and ensure RLS reads role from app_metadata, never user_metadata.

F-10Public child-account restoration pageMedium

restore.unomundi.com still serves a public "Restore Account" page (email + OTP, "reactivate before permanent deletion"). Confirm OTP entropy and per-email/per-IP rate limiting so it cannot be used to enumerate or brute-force guardian accounts. Auth-gate or rate-limit aggressively.

F-11GDPR export bucket reachable by the live tokenMedium

The data-exports bucket (destination for GDPR Art.15 child-profile exports) remains reachable by the still-valid service_role token from C-1. Not re-enumerated this week to limit footprint. Resolved automatically once C-1 is rotated and Storage access is re-scoped.
