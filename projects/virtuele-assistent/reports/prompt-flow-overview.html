1 End-to-end data flow

Gebruiker typt een vraag, agent-frontend

De chat-client onderschept de POST en stuurt de body eerst langs /ai/redact (PII-redactie) voordat hij naar de backend gaat.

↓POST /ai/stream/chat/{tenant}/chat (via nginx)

agent-backend, ChatHttpRoute

Parseert de berichten in twee delen: conversationHistory() = eerdere turns als gestructureerde user/assistant-berichten, en lastUserMessage = de huidige vraag (split op de laatste user-turn).

↓systeemprompt opbouwen

PromptAssemblyService, systeemprompt

Bouwt de systeemprompt (zie sectie 2), daarna injecteert PromptUtils.injectDateTime de runtime-waarden {{CURRENT_DATE}}, {{CURRENT_TIME}}, {{CURRENT_DATETIME}}.

↓agent.run(lastUserMessage) + systeemprompt + ConversationHistory + tools

Agent-strategie (Koog), nodes

classify, dan PROCEED / DISAMBIGUATE / REDIRECT, tool-aanroepen (RAG) en antwoordgeneratie. Per node een eigen prompt (zie sectie 3).

↓antwoord streamt terug (data-stream frames)

agent-frontend, StructuredAnswerText

Parseert [[STEPS]] en [[FOLLOWUPS]] uit de antwoordtekst: proza als markdown, stappen als genummerde lijst, vervolgvragen als klikbare chips (klik = volgende user-turn). Zie sectie 4.

2 Systeemprompt-assemblage

assembleSystemPrompt(tenantId, label = EnvironmentConfig.promptLabel, directPrompt). label = production in prod, test elders.

directPrompt = true?

Ja: haal {tenant}_systemprompt vers uit Langfuse (geen cache, geen sjabloon). Bedoeld voor live prompt-bewerking tijdens demo's.

↓nee

Per-tenant variabelen uit DB (tenant_configurations)?

Geen variabelen gezet, dan legacy {tenant}_systemprompt uit Langfuse. Wel variabelen, dan sjabloon + substitutie:

Sjabloon kiezen

live generic_system_prompt_v3 (fallback v2).

!173 als tenant refactor/system-prompt-main heeft gekozen (allow-list), die eerst.

Basis-variabelen

{{bot_name}}, {{email}}, {{phone}}, {{address}}, schrijfstijl, perspectief enz. uit TenantPromptVariables (derived map).

Fallback bij fout

Lukt het sjabloon laden of substitueren niet, dan terug naar legacy {tenant}_systemprompt.

Content-blokken (alleen refactor-sjabloon) !173

  2. het live Langfuse-fragment, anders
  3. de hardcoded fallback-constante (RefactorTemplateDefaults), zodat assemblage nooit breekt als Langfuse plat ligt.

3 Agent-strategie en per-node prompts

Alle node-prompts komen uit Langfuse via StrategyPromptService (label = promptLabel, 5-min cache). Naast de systeemprompt krijgt elke node-aanroep de ConversationHistory (gestructureerde turns) mee.

nodeClassify, classify_prompt

Klein model (GPT-4.1-mini), temperatuur 0, org-systeemprompt eraf. Bepaalt de route.

↓routing-beslissing

PROCEED

nodeCallLLM, toolcall_prompt → RAG-tools → nodeHandleToolResults, answer_prompt (of answer_forced_prompt; retry_prompt bij tool-fout) → antwoord streamt.

DISAMBIGUATE

nodeDisambiguate, disambiguate_prompt → streamt een verhelderende vraag, geen tools.

REDIRECT

nodeRedirect, redirect_prompt → verwijst door / buiten scope.

Feedback-lus bij tool-gedrag: giveFeedbackToCallTools met feedback_prompt. Los daarvan: pii_warning_instruction. NB: review op !173 merkte op dat system(...) in deze nodes na user(message) staat (niet-canoniek); bewust uitgesteld naar een eval-gedekte MR.

4 Antwoord-markers naar UI in ontwikkeling

Het answer_prompt instrueert het model om (optioneel) twee markerblokken in de platte antwoordtekst te zetten. De frontend (StructuredAnswerText) verwerkt ze:

proza

Tekst vóór de eerste marker, gerenderd als markdown (links, vet enz.).

[[STEPS]]

Eén actie per regel (alleen procedureel) → genummerde "stappen"-lijst, de UI nummert.

[[FOLLOWUPS]]

1 tot 3 vragen, altijd als laatste → klikbare chips, klik = volgende user-turn.

Rauwe markers worden uit de proza gestript; een half-gestreamde marker flitst niet. Vervolgvragen worden pas klikbaar als het bericht klaar is. Let op: nog geen enkel Langfuse-prompt zendt deze markers, dus live verschijnen ze pas als het answer-prompt in Langfuse staat.
