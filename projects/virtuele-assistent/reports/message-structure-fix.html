Virtuele Assistent · fix/messagestructure
Implemented fix

Send the conversation as structured turns, not a flattened blob

The model now receives real user and assistant messages. No feature flag, the behavior is changed directly.

What changed in one paragraph

Instead of joining the whole conversation into one user: / assistant: text blob and sending it as a single user message, the backend now runs the agent with only the latest user message and replays the prior turns as proper user and assistant messages. Prior tool-call steps and empty messages are dropped, so the model sees a clean, structured conversation. Retrieval is unchanged. No switch: this is the new default.

Before and after

Before

One user message containing the whole transcript.

system: [org prompt]
user: "user: Ik wil een paspoort aanvragen
assistant: U kunt online ...

system: [toolcall instruction]

After

Real role-tagged turns.

system: [org prompt]
user: Ik wil een paspoort aanvragen
assistant: U kunt online ...
user: en wat kost dat
system: [toolcall instruction]

The change, file by file

New file agent-backend/src/main/kotlin/assistant/rag/ConversationHistory.kt

A coroutine-context carrier for the prior turns, mirroring the existing OriginalQueryContext pattern. It holds a list of ConversationTurn(role, text).

data class ConversationTurn(val role: String, val text: String)

class ConversationHistory(val turns: List<ConversationTurn>) : CoroutineContext.Element {
    companion object Key : CoroutineContext.Key<ConversationHistory>
    override val key get() = Key
}

Why this is correct and safe

ConcernHow it is handled
Library / agent signatureUnchanged. Agent still runs on a String (the latest message); prior turns travel via coroutine context, exactly like OriginalQueryContext. No fork of koog-ktor-agent.
Replaying prior tool stepsAvoided. Only real user and assistant text turns are replayed; tool-call steps and empty messages are filtered out, so Koog's tool-call/result pairing inside the live run is untouched.
PIIUnchanged. History is built from the already-redacted messages list.
RetrievalUnchanged. OriginalQueryContext(lastUserMessage) still drives HyDE and search. This change is orthogonal to the retrieval-rewrite item.
API usedVerified against Koog 0.6.0: PromptBuilder has user() and assistant(); currentCoroutineContext() is already used elsewhere in the codebase (RagToolFactory).
Prompt cachingImproves. The system prompt plus older turns form a stable prefix, so each new turn caches more of the conversation rather than rebuilding one growing blob.

Build verification Compiles

./gradlew compileKotlin on JDK 17 returns BUILD SUCCESSFUL. The change compiles cleanly. Still recommended before merge: a multi-turn smoke test and an eval run (below).

How to validate before merge

  • Compile: ./gradlew compileKotlin (JDK 17).
  • Smoke test multi-turn: ask a question, then a coreferent follow-up ("en wat kost dat?"), and confirm the answer uses the earlier context.
  • Eval: run the existing Langfuse evals (answer_relevance_v2, faithfulness_v2) on a sample and compare to the current production baseline.
  • Trace check: in a new trace, the answer generation should show separate user and assistant messages, not one blob with user: / assistant: prefixes.
