Ticket detection, shipped

commit d97e40a · branch clean-slate
What changed. Opt-in Detect tickets checkbox under a new Assistant features section in Settings. When on, the call assistant watches for fully-formed user stories during the call and drops a structured ticket card into the chat stream when one emerges.

How it decides

The LLM call now returns a discriminated JSON instead of a yes/no speak flag:

{ "kind": "chat", "message": "..." } { "kind": "ticket", "ticket": { priority, title, user_story, acceptance, tags, effort } } { "kind": "silent" }

Tickets only fire when a story is genuinely complete: an actor, a capability, an outcome, and at least two concrete acceptance criteria. The running ticket list is fed back into every prompt so duplicates are ruled out.

Server-side fixups

  • Sequential IDs. Backend assigns T-001, T-002 so the model doesn't try to invent project codes.
  • Priority normalised. MUST / HIGH / MEDIUM / LOW, with P0..P4, URGENT, CRITICAL aliased to the canonical set.
  • Effort normalised. S / M / L / XL, longhand aliases collapsed.
  • Duplicate guard. Running list of captured tickets is injected into every passive prompt with a "do not duplicate" instruction.
  • Parse-failure logging. Bad JSON from the model is logged with the offending text so we can see what came back, instead of silently going quiet.

Where it lives

  • Backend. src-tauri/src/assistant/chat.rs, src-tauri/src/config.rs, src-tauri/src/lib.rs
  • Frontend. src/components/v2/TicketCard.tsx, src/components/v2/AssistantChat.tsx, src/components/Settings.tsx

Try it

  • Restart npx tauri dev.
  • Settings, tick Detect tickets, save.
  • Start a call and articulate a story. Something like, as an engineer I want X so Y, and it should also handle Z and A will tend to land a ticket within one tick.

About the silent loop

The earlier "assistant turns stopped" symptom should be easier to diagnose now: parse failures are logged with the offending JSON, and the loop continues on errors instead of going quiet. If it still falls silent, grab any Assistant tick error: warnings from the log and that should point to an Anthropic-side issue (rate limit, model error) rather than a permanent stall.
