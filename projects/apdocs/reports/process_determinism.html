APDOCS — Process & Determinism Map

Aviation Back-to-Birth document review is a regulatory workflow. Every claim the system makes must be traceable to either a deterministic rule or an explicitly-flagged AI judgement. This page maps each pipeline step to its determinism profile.

Determinism levels

Deterministic

Same input always produces the same output. Rule-based, repeatable, audit-friendly. Suitable for compliance evidence. Implemented in code, inspectable in source control.

Hybrid

Deterministic structure operating on noisy or imperfect input (OCR text, fuzzy matching, threshold-driven). Output is repeatable for a given input but the input itself may carry errors that propagate. Requires a confidence score and downstream verification.

Non-deterministic

Claude / LLM judgement. Output may vary across runs even with identical input. Used where deterministic rules cannot apply (free-form text, fuzzy semantic match, vision tasks). Every output must be reviewable, explainable, and either confirmed by a human or by a deterministic counter-check.

The pipeline (9 phases, 26 operations)

A
Package ingestion
Walk the source tree. Map folder + filename signals to lifecycle stages and document slots.
A1. File-system walk Deterministic
Recursive directory traversal, file hashing, size and extension recording.
Implementation
build_join.py — Python pathlib.rglob
Why det
OS-level operation, no judgement involved
A2. Stage classification from folder name Deterministic
Parse 2. 994738 SV TSN 11,343 (IHI) into kind=SV, ESN=994738, TSN=11343, vendor=IHI.
Implementation
Regex STAGE_RX, TSN_RX, VENDOR_RX
Risk
Depends on APOC's naming convention being followed. Misnamed folders fall through to LOOSE bucket.
A3. Doc-slot from filename prefix Deterministic
Numeric prefix maps to canonical slot: 1.=Certification, 3.=LLP Status, 11.=Operation Statement, etc.
Coverage
~23% of files classifiable by filename alone
Risk
The (dragged) misfile shows mismatch between filename declared stage and folder location. Detection is itself deterministic.
A4. Doc-type fallback for unclassified files Non-deterministic
For the 77% with no slot prefix, OCR the first page and ask Claude to classify against a known type catalogue. Returns type + confidence.
Why non-det
Free-form text classification; LLM may pick differently across runs on edge cases
Mitigation
Require confidence ≥ 0.8 to auto-accept. Below that, route to OIL for human review.
Risk: Mis-classification routes a document to the wrong slot, causing false "missing-doc" flags downstream. Always pair with deterministic counter-check (e.g. "if slot 1 missing for an SV stage, but a doc classified as Certification is in the folder, prefer the classified one").
B
Text extraction
Get text out of PDFs. Native text-layer wherever possible, OCR otherwise.
B1. Text-layer PDF extraction Deterministic
If the PDF has a native text layer, extract via pdftotext -layout. 994738's LLP Trace dossiers were assembled in a system, so they have clean text.
Coverage
~10% of files (the system-generated dossiers + a few digital docs)
Tool
poppler pdftotext, deterministic
B2. Rasterize and Tesseract OCR Hybrid
For image-only PDFs (~80%), pdftoppm -r 300 -gray then tesseract --psm 6. Same input always produces the same output, but OCR introduces character-level noise.
Throughput
~16s per dossier; 320s for 20 dossiers (120 pages)
Known errors
0↔O, 5↔S, 1↔I↔l, J↔I, dropped leading characters (e.g. DD763172→D763172)
Why hybrid
Process is repeatable but input fidelity (scan quality, layout) determines accuracy
B3. OCR fallback for poor-quality scans Non-deterministic
When Tesseract confidence is below threshold or output is gibberish, escalate to Claude vision. Slower and costs tokens, but recovers text from low-contrast / handwritten / stamped pages where Tesseract fails.
When invoked
Tesseract page confidence < 70% or known-fields not found in regex pass
Cost
~€0.05-0.15 per page vs €0 for Tesseract
Why non-det
Vision model output may vary across runs; same scan can produce slightly different text
Risk: Field values produced by vision LLM are not citable evidence on their own. Always render an image crop alongside the extracted value in the UI, so a human can verify.
B4. Date / signature / stamp recovery Non-deterministic
Stylised dates ("2b AgR20}" out of Tesseract → "26 Apr 2017"), signature presence, stamp presence. Vision LLM only.
Why non-det
Visual judgement, no rule-based shortcut for handwriting / stylised glyphs
Mitigation
Output a binary present/absent + a confidence + an image crop. If signature missing or stamp missing → mandatory OIL item, never auto-resolved.
C
Field extraction
Pull structured values (PN, SN, TSN, CSN, dates, MSN, registration) from text.
C1. Anchor-based regex on clean text Deterministic
For 994738, anchor on engine ESN and known part PN (from filename), split before/after to recover engine TSN/CSN, dates, reason. 180 rows parsed, 0 inconsistencies.
Implementation
build_tree.py · parse_row()
Why det
Pure regex, anchored on stable identifiers
C2. Tokenised regex on OCR'd text Hybrid
For 779125, OCR adds prefix junk (_, ,) and inconsistent spacing. Tokenize, find known item codes (211, 213, 221...) anywhere in first 3 tokens, then look for PN-shaped and SN-shaped tokens.
Why hybrid
Deterministic algorithm, but the input text has OCR noise that may cause misses or false positives
Counter-measure
Each LLP appears in multiple snapshots; majority-vote across dossiers
C3. LLM extraction for irregular forms Non-deterministic
For Bills of Sale, IACS letters, and free-form Operation Statements, regex breaks down. Send the OCR'd text + a typed JSON schema to Claude, validate the JSON, retry if invalid.
When invoked
Doc type ∈ {BoS, IACS, Operation Statement, Operator Letter}
Mitigation
Schema validation rejects malformed responses. Two-pass: extract, then verify by re-asking the model to cite the source line for each field.
C4. SN canonicalisation for OCR drift Deterministic
Lowercase, strip dashes, fold confusable characters: O→0, S→5, I→1, L→1, J→1, B→8, Z→2. Used only for matching, never for display.
Risk
If a real PN happens to differ only by a confusable character, canonicalisation may merge two distinct parts. Counter: also compare un-canonicalised PN; require both forms to agree before declaring a match.
D
Tree construction
From extracted fields, build the engine timeline and per-LLP histories.
D1. Engine timeline assembly Deterministic
Group extracted rows by engine TSN, sort events at same TSN by reason precedence (DE-REG before NEW REG, EOL before INSTALL). Open stage on INSTALL/NEW REG, close on EOL/DE-REG/SV-EOL/REMOVAL.
Why det
Pure data structure operations on validated input
D2. Cross-LLP consistency check Deterministic
For each (engine_TSN, reason) pair, every LLP that has a row should agree on operator, registration, MSN. Disagreement = data integrity issue.
Result on 994738
180 rows checked, 0 inconsistencies
D3. Snapshot reconciliation across dossiers Hybrid
For 779125, 20 dossiers each contain status snapshots. Group by (issue_date, A/C, position). Aggregate metadata by majority vote (Counter.most_common(1)).
Why hybrid
OCR errors mean different dossiers report slightly different values for the same field. Majority vote heals most cases. Edge cases require human review.
E
Swap detection
When the same LLP position carries a different SN at different snapshots, detect and confirm.
E1. Per-position SN comparison Deterministic
For each item code, list all (snapshot, PN, SN) tuples. If the unique SN set has size > 1, candidate swap.
E2. Levenshtein-based OCR-noise filter Hybrid
Canonicalise SN strings, compute pairwise Levenshtein distance. Distance ≤ 2 (after canonicalisation) = OCR artifact. Distance > 2 = real swap. Found 3 real swaps + 5 artifacts in 779125.
Why hybrid
Threshold of 2 is a calibrated judgement, not a derived constant
Calibration
Tuned on the 779125 dataset; should be re-tuned per OCR quality and per part SN length distribution
E3. Swap-event timing inference Non-deterministic
Given known SN at snapshot T1 and different SN at T2, the swap happened in some shop visit between them. The exact SV is determined by reading the SV's LLP Status and matching SNs. Until that's done, "during SV #N or SV #N+1" is the answer.
Why non-det
Sometimes shop reports are ambiguous about which removal/install happened on which date; LLM has to read free text
Mitigation
If multiple SVs are candidates, raise as OIL item and let a human pick
F
Validation
Run rule families. Most are deterministic. The few that aren't are explicitly flagged.
F1. TSN/CSN monotonicity Deterministic
For any LLP across the timeline, TSN and CSN must never decrease. If they do, data error.
F2. Operator handover continuity Deterministic
Off-wing TSN of operator N must equal on-wing TSN of operator N+1. Gaps = unaccounted operating period = compliance issue.
F3. Doc-slot completeness per stage kind Deterministic
SV folder requires slots {1,2,3,4,5,6}. OP folder requires {1,3,4,5,11}. MFG requires {1,2,3}. Anything missing → flag.
F4. LLP-dossier vs LLP-Status diff Deterministic
Set of LLPs in any SV's LLP Status should equal set of dossiers in 0. LLP Trace/. Found the missing TURBINE REAR FRAME in 994738 by exactly this rule.
F5. Cross-ESN contamination Deterministic
Filename ESN must match package ESN. Catches the 779114 / 779352 misfiles inside the 779125 package.
F6. Filename-stage vs folder-stage Deterministic
Filename declares "OP TSN 51,434" but file lives in /6. SV TSN 48,986/ → flag misfile. The (dragged) annotation in the filename is icing.
F7. IACS wording compliance Non-deterministic
Spec slide 8: "Standard wording (or acceptable variation) referencing Chicago Convention". The acceptable variations are not enumerated. Claude reads the IACS, scores wording compliance, cites the deviation if any.
Why non-det
Natural language judgement; "acceptable" is a fuzzy concept the OEM and the carrier and the lessor each interpret differently
Mitigation
Build a "known acceptable variations" list from successful prior validations. Anything new escalates to OIL with the LLM's analysis attached.
F8. Re-registration vs swap distinction Non-deterministic
994738 at TSN 1,006: TI-BCG → N936TA, both on TACA. Looks like an aircraft swap by a naïve rule. Actually a US Federal re-registration of the same airframe, same MSN. Distinguishing this requires reading the operator letter.
Why non-det
The signal is in free-text justification documents
Mitigation
If MSN unchanged across the transition, treat as re-reg by default. Only escalate if MSN also changes.
F9. Thrust rerate authorisation Non-deterministic
994738 changed E6 (17,390 lbf) → E7 (18,820 lbf) → E6 across operators. Each transition needs an SB / Service Bulletin authorising the rerate. Detecting the rerate is deterministic; detecting the SB is non-deterministic.
Mitigation
If SB cited in the operator certification text, accept. Otherwise, mandatory OIL item.
F10. PN family change requires SB / AD Deterministic
Detecting that PN family changed (336-031-632-0 → 338-061-627-0 for 779125 TURBINE REAR FRAME) is deterministic. The follow-up "is there an SB or AD authorising it?" is a search task; raise OIL if not found.
G
Reporting & OIL
Build the Open Item List and ranking. Tree visualisation. Trace Pack.
G1. OIL assembly Deterministic
Collect all flags from F1-F10 into a structured list. Each item: rule_id, severity, target (file/component/stage), evidence path.
G2. Severity ranking Non-deterministic
Items are tiered as Critical / High / Medium / Low. The tiering rules are 80% deterministic (e.g. missing certificate = Critical), but edge cases (e.g. SN OCR ambiguity) need judgement.
Mitigation
Default tiering by deterministic rule. Allow LLM to upgrade severity, never downgrade. All upgrades logged with rationale.
G3. Tree rendering Deterministic
JSON → HTML / SVG / ASCII. Pure layout.
G4. Trace Pack PDF cover summary Non-deterministic
"This engine flew 27,547 hours over 15 years across 3 operators. All LLPs are factory-original. One dossier is missing." Free-form prose, generated by Claude from the deterministic data.
Mitigation
Cite every numeric claim back to source. The summary is rendering, the underlying data is the evidence.
H
Smart Search
"IACS for PN 10-210101-006 of MSN 1451 in year 2021"
H1. Structured query (PN, SN, ESN, MSN, year, doc type) Deterministic
When the user gives a structured query, hit the index directly. SQL or Cognitive Search filter.
H2. Natural-language query Non-deterministic
"Show me all the engines that had a Turbine Rear Frame swap between 2018 and 2022." Claude parses, generates a structured query, runs it deterministically, returns the result.
Mitigation
Always show the parsed structured query to the user before executing. They can correct it.

Architectural rules I converged on

1Deterministic by default

If a deterministic rule can solve it, use the rule. Reach for an LLM only when no rule applies. Cheaper, faster, auditable, and the result is identical across re-runs (which matters for compliance evidence).

2Every LLM output is a hypothesis, not a fact

Claude's output is a candidate. It must be either confirmed by a human reviewer or by a deterministic counter-check before becoming part of the official record. Every LLM-derived field carries provenance and confidence.

3Always cite source

Every extracted value (PN, SN, TSN, date) must point back to a specific (file, page, region). The UI shows the image crop next to the value. This makes reviewer verification a 5-second click instead of a 5-minute hunt.

4LLM never downgrades severity

Deterministic rules raise flags at a default severity. The LLM may upgrade severity (e.g. "this is actually Critical because the missing IACS covers the operator change") but never downgrade. Reasons for upgrades are logged.

5Heal OCR by majority vote

Each fact (PN, SN, TSN at date) appears in multiple documents across the package. Aggregate by majority across observations. This turns noisy OCR into clean structured data without needing perfect OCR.

6Cache OCR aggressively

OCR is a one-time cost per file. Once a file's .ocr.txt sidecar exists, never re-OCR unless the source PDF hash changes. This makes the system idempotent and predictable.
