How everything connects

Every file in an APOC package can be located by a small number of keys. Once each document is tagged with those keys, every BtB question becomes a graph traversal. This page enumerates the 10 keys, the 12 entity types, and shows a worked traversal from a single PDF outward to everything it touches.

The 10 keys

Every document carries some subset of these. The more keys a document carries, the more places it joins to in the graph.

KeyFormatJoinsWhere it lives in source
ESN (Engine Serial Number) 6 digits, e.g. 994738 Document → Engine → Lifecycle → almost every other entity Folder name, filename, content header, BoS, EASA Form 1
PN + SN e.g. 1865M51P03 / GWN0L0KT Document → Component instance → Position → Engine LLP Trace filename, LLP Status rows, EASA Form 1, certificates
Item code (position) 3 digits or alphanum, e.g. 211, L002 Position → Component over time (survives swaps) Left column of any LLP Status. Maps to OEM module map.
MSN (Aircraft Mfr SN) 3-4 digits, e.g. 586 Document → Aircraft → Operator period → Engine LLP Trace lineage table, Operator Statement, IACS
Aircraft Registration e.g. TI-BCG, I-BIXQ, 5Y-FFE Secondary aircraft key; can change while MSN is constant (re-registrations) LLP Trace lineage, Operator Statement, techlog
TSN (Time Since New) Integer hours, e.g. 11,343 Event → Lifecycle position → Folder boundary Folder name, LLP Status, certification, operator statement
CSN (Cycles Since New) Integer cycles, e.g. 7,694 Same as TSN, alternative time scale Same as TSN
Date e.g. 10-Dec-2012, 29 Apr 2009 Event → Calendar; ties to operator periods Certificate, Operator Statement, LLP Status issue date, IACS
Workorder Numeric, e.g. 704010655 Manufacture event → OEM cert → Components EASA Form 1, Snecma/GE delivery cert
Operator / MRO name Free text, e.g. TACA, IHI, Alitalia Stage → Party → Document set authority Folder name suffix, document letterhead, signature block

Connections across packages

The same keys also bridge between distinct engine packages. A few examples from the two packages we've analysed.

ESN 994738 — CF34-10E

Purchased from Engine Lease Finance Corporation. Atlantic Aircraft Holding Two Ltd was the original seller to ELFC in 2009 (per Bill of Sale, Item 11).

Shared seller / lessor Engine Lease Finance Corp.

ESN 779125 — CFM56-5B2/P

Also purchased from ELFC. The "Additional records ELFC/" folder contains 120 loose documents from the lessor for this engine.

ESN 779125 package root

Stray file: 779114 NIS 2007 (1).pdf

Foreign-ESN reference 779114

ESN 779114 (sibling engine)

Not in our data, but referenced. Likely a sibling CFM56 on Alitalia, sourced from the same lessor. Could trigger a cross-package join when we encounter 779114's package.

ESN 994738 Kenya Airways period

MSN 586 → registration 5Y-FFE → engine on left position (assumed pos #1) at install.

Coincidence on MSN value MSN 586

ESN 779125 Alitalia period

MSN 586 → registration I-BIXQ. Same MSN number, but different aircraft: Embraer ERJ-190 vs Airbus A321-112. The validator must NOT join these.

The MSN coincidence is a reminder: MSN is unique within an aircraft OEM, not globally. A real index keys aircraft as (OEM, MSN) — Embraer 586 ≠ Airbus 586.

What the index needs to look like

The relationship graph above becomes a small relational schema. Every join in the graph maps to a foreign key here. Storage: Postgres or Cosmos; search overlay: Azure AI Search.

engines ( esn text PK, -- 994738 oem text, -- General Electric / Snecma type text, -- CF34-10E, CFM56-5B2/P manufactured date, workorder text, status text -- in-service / EOL / sold ) aircraft ( oem text, -- Embraer, Airbus msn text, current_reg text, type text, -- ERJ-190, A321-112 PRIMARY KEY (oem, msn) ) positions ( esn text REFERENCES engines, item_code text, -- 211, 213, L002 description text, life_limit integer, -- cycles PRIMARY KEY (esn, item_code) ) components ( -- a serialized LLP instance pn text, sn text, description text, oem text, PRIMARY KEY (pn, sn) ) stages ( -- lifecycle period id uuid PK, esn text REFERENCES engines, kind text, -- MFG / SV / OP start_tsn integer, end_tsn integer, operator text, -- TACA / IHI / Alitalia / ... aircraft_oem text, aircraft_msn text, registration text, start_date date, end_date date, FOREIGN KEY (aircraft_oem, aircraft_msn) REFERENCES aircraft ) events ( -- discrete event within a stage id uuid PK, esn text REFERENCES engines, tsn integer, csn integer, reason text, -- INSTALL / DE-REG / NEW REG / SV-EOL / EOL / REMOVAL date date ) position_history ( -- which component occupied a position when esn text, item_code text, pn text, sn text, start_event uuid REFERENCES events, end_event uuid REFERENCES events, FOREIGN KEY (esn, item_code) REFERENCES positions, FOREIGN KEY (pn, sn) REFERENCES components ) documents ( id uuid PK, esn text REFERENCES engines, stage_id uuid REFERENCES stages, doc_type text, -- Certification / LLP Status / IACS / BoS / ... doc_slot integer, -- 1..12 if numeric prefix; NULL otherwise path text, hash text, -- sha256 of file bytes page_count integer, ocr_done boolean, ocr_text text -- OCR'd text body ) document_fields ( -- extracted structured fields doc_id uuid REFERENCES documents, field_name text, -- e.g. 'pn', 'sn', 'tsn', 'msn', 'signature_present' field_value text, source_page integer, source_bbox text, -- bounding box for citation confidence real, source_method text -- 'regex' / 'tesseract' / 'claude-vision' ) flags ( -- validation findings, the OIL id uuid PK, esn text, rule_id text, -- F1..F10 severity text, -- critical / high / medium / low target_type text, -- doc / stage / component / position target_id uuid, evidence_path text, rationale text, source_method text -- 'deterministic' / 'hybrid' / 'claude' )

Critical detail: document_fields.source_method and flags.source_method tag every fact with its determinism profile. A reviewer can filter the index for "non-deterministic facts in this Trace Pack" and audit them in one query. That's the determinism contract from the skill enforced at storage level.
