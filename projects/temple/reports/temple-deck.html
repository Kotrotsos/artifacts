incredicorp07
Blueprints

One engine. Three shapes of work.

A blueprint is declarative data, not code: states, legal transitions, guards, invariants, role policy. The engine runs whatever shape you declare.

Flow

linear-like · state machine

Issues move through legal transitions only. Guards block half-done work, invariants make bad states unreachable, policy says who may approve.

Pages

notion-like · typed databases

Databases hold pages with typed properties and a markdown body. Loosely structured, fully governed, every edit versioned.

Wiki

free-form · revisions + backlinks

The loosest shape: markdown pages in a tree. An immutable revision on every save, [[backlinks]] extracted automatically.

incredicorp09
Trust

“Verified” is a gate, not a sticker.

L1
Algebra
One initial state, every transition references real states.
L2
Reachability
No unreachable states, no dead ends, terminals stay terminal.
L3
Soundness
No path of legal moves can reach a state that violates an invariant.
L4
Property
200 randomised action sequences, invariants hold throughout.
$ npm run verify
PASS  blueprint: flow      L1 algebra ok · L2 reachability ok · L3 soundness ok · L4 property ok
PASS  blueprint: pages     L1 ok · L2 ok · L3 ok · L4 ok
PASS  blueprint: wiki      L1 ok · L2 ok · L3 ok · L4 ok

A blueprint that fails any level does not load. Change the spec, the verifier re-proves it before the engine will run it.
