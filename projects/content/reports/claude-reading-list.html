Practical Claude Reading List

Twelve articles worth reading this week. Curated for builders and decision-makers. Sourced 2026-05-14.

What this is. The strongest practical writing about Claude this month. Filtered for: actually used in production, named tradeoffs, opinion held, no marketing fluff. Ordered roughly by "read first." Five categories.

1. Architecture, the mental model

Understanding Claude Code's Full Stack: MCP, Skills, Subagents, and Hooks Explained

alexop.dev
architecturepower-user

Why read. The clearest one-page mental model for how the four extensibility primitives fit together. MCP is the data layer, Skills are reusable instructions, Subagents are isolated contexts, Hooks are deterministic control. If you have been confused about which to reach for, this resolves it.

A Mental Model for Claude Code: Skills, Subagents, and Plugins

Level Up Coding, Dean Blank
architecturedecision-making

Why read. Companion to alexop's piece. Frames the decision tree: when do you write a skill, when do you spawn a subagent, when do you ship a plugin. Plugin layer adds the publishing dimension most other guides skip.

Claude Code: Hooks, Subagents, and Skills, Complete Guide

DEV Community, Owen Fox
hookssubagentsskills

Why read. Working examples for each of the 25 hook lifecycle points. Particularly useful: the "block at submit time, not at write time" recommendation, which corrects a common mistake that breaks Claude's reasoning chain.

2. Opus 4.7, what actually changed

Claude Opus 4.7 Review: What Actually Changed and What Got Worse

MindStudio
opus-4.7honest-review

Why read. Names the regression. SWE-Bench Pro jumped from 53.4% to 64.3%, task abandonment dropped 60%, but web research quality took a measurable hit and the tokenizer change bumps token counts 12 to 18% on typical workloads. This is the only Opus 4.7 review that calls out the loss.

Claude Opus 4.7 Best Practices: Detailed Plans Win

claudefa.st
opus-4.7prompting

Why read. The single best operational tip for 4.7: ask for a plan first with an explicit "don't implement yet" guard phrase, annotate the plan, send back. Without the guard phrase, 4.7 dives into code. With it, plan quality jumps substantially.

Opus 4.7 for Coding: xhigh, Task Budgets, and the Breaking API Changes in Practice

Tygart Media
opus-4.7api

Why read. The piece that warns you about the breaking API changes before they bite. Names what changed at the API level, what to migrate, what to leave alone. Read before you upgrade in production.

3. Production deployment, the long game

Anthropic: Building Production AI Agents, Lessons from Claude Code and Enterprise Deployments

ZenML LLMOps Database
productionenterprise

Why read. The most-cited number from this piece: 90% of agent failures are bad prompts, not bad models. Read alongside the Uber budget story, this is the operational counterweight. If your agents are failing, the model probably is not the problem.

Claude Managed Agents: Complete Guide to Building Production AI Agents (2026)

The AI Corner
managed-agentsinfra

Why read. Names the timeline shift: working demo in 2 days, production in 3 months, was the old shape. With Managed Agents, Notion, Rakuten, and Asana report 10x compression. Read for the deployment shape, not the vendor pitch.

State of AI Agents 2026: Five Enterprise Trends

arcade.dev
productiondata

Why read. The integration finding: 46% of enterprise respondents cite integration with existing systems as the top challenge, not model capability. This is the practical headline behind every "AI is harder than it looks" anecdote.

4. Power user playbooks

Claude Code Skills: A Practical 2026 Guide

Nimbalyst
skillsworkflow

Why read. Most skill guides explain what skills are. This one shows the file structure, the YAML frontmatter rules, and which patterns reuse cleanly across projects. The practical part most other guides skip.

Claude Code Best Practices: Lessons From Real Projects

ranthebuilder.cloud
workflowlessons

Why read. Focused on CLAUDE.md as a configuration practice. Names the 200-line limit, the conventions worth defining, the review checklists. If you have not written a real CLAUDE.md yet, start here.

5. Where Claude fits in the model landscape

GPT-5.5 vs Claude Opus 4.7 vs Gemini 3.1 Pro for Builders

MindStudio
comparisonrouting

Why read. The practical routing rule: agentic coding to Claude, interactive chat and high-volume RAG to Gemini, GPT-5.5 as the balanced fallback. Skips the benchmark theater and lands on a one-paragraph decision rule any team can apply.

Reading order, if you only pick three

  1. alexop's full-stack explainer, for the mental model.
  2. MindStudio's 4.7 review, for the honest tradeoff list.
  3. ZenML's production lessons, for the "it is your prompts, not the model" reframe.

What I deliberately skipped

  • Generic "Top 10 prompts for Claude" listicles. Read like SEO bait, no operational density.
  • Benchmark roundups without opinion. Numbers without recommendation is just a table.
  • Anything in the "Claude is dead, here is what's next" genre. Pattern flagged in CLAUDE.md as an AI tell.
  • Vendor-driven enterprise guides without independent customer detail.
