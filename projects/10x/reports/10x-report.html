How this was mined

Distilled from the real record in ~/.claude/projects/: 880 session transcripts (481 MB) from 2026-04-15 to 2026-06-03. A deterministic extractor produced per-project digests (timing, tool and shell-command histograms, every message typed, every correction). A multi-agent workflow then produced 66 findings, merged them to 23, and an adversarial verifier re-checked each against the evidence and deflated the optimistic estimates.

Honest caveats. "Active hours" (gaps under 5 min) is the real time figure; ignore "wall hours." The friction percentage is noisy because your own review subagents send prompts containing words like "broken" and "wrong," so it is inflated in build projects; verbatim quotes are used instead. PERSONAL-print's 1,539 "messages" are mostly automated poll-loop notifications, not hand typing. Per-command timing was not available, so hours are estimates: trust the ranking order more than the absolute numbers.

The findings that matter most

A. You rebuild context every session because memory is mandated but not wired grounded

SessionStart hook only prints a reminder; Memento search used in under 1% of sessions; Read is your top tool at 4,032 calls re-establishing context; you re-run /init and re-paste logins; zero STATUS.md files across 38 projects.
Fix. SessionStart hook that actually recalls, SessionEnd hook that stores a closure record and writes STATUS.md. The backbone every other fix rides on.

B. You design after you build, then pay for the rework grounded

"implement it. We will be creating the design later on." then "this looks offbrand, redo the design." (subradar)
"make it native looking, it looks bad now. look at how tiktok looks, make it look like that." (mailplus, after the build was done)
Figma MCP and your design-review skills were available and unused. askwell designed first and barely reworked.
Fix. Mockups and locked Tailwind tokens before any component. Gate the first build on design-review.

C. You run your review and eval machinery by hand, hundreds of times grounded

Build timelines saturated with repeated "Review this change for security vulnerabilities" and "impartial code reviewer" prompts. The GREEN/AMBER/RED reviewer block ran in 30 projects, pasted by hand 300+ times. A real XSS reached manual review in mailplus.
Fix. Install the agent-eval reviewer as a user-wide hook, add husky + lint-staged + CI so basic gates run automatically.

D. Opus runs everything, including work a faster model should do grounded

Opus is 77.9% of model calls; Sonnet 1.6%, Haiku 1.0%. Opus runs the browse skill's web extraction (2,607 calls), the poll loops, and the review subagents, all latency-sensitive or low-complexity.
Fix. Haiku for search and triage, Sonnet for mid-size review, Opus for real reasoning. Start by routing browse extraction to Haiku.

F. Secrets keep landing in the chat grounded

A live Google OAuth client secret (subradar), the Anthropic key, and a user password (ppry...) in askwell, all sitting in saved transcripts on disk.
Fix. Rotate the three now. Add a secret-scan hook. Reference .env keys by name, never paste the value.

G. Every new product repeats the same two rituals grounded

"create media, blurbs, taglines, positioning statement, pitch" then pitch deck, demo, viability research. (askwell)
"can you connect github yourself?" then "create the github skill please" then "wire up the postgresql database." (askwell)
Fix. A /launch-kit skill for naming, positioning, pitch and demo, and a /ship-it skill for GitHub plus Railway plus Postgres plus env.

H. Sprawl and reinvention drain time and momentum partial

38 projects in 7 weeks, 100+ folders, 55 to 60% graveyard. archer rebuilt 7x, RAG 5-6x, session-readers 6x. cd is your most common shell command at 3,026 calls. ~32 GB of datasets committed to git.
Fix. A 3-project WIP limit, a monthly graveyard prune, a shared-core monorepo, and datasets out of git.
