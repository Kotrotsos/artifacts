  • canon (orientation canonicalization at full resolution, 4 lossless query variants instead of 18 lossy ones) fixes rotation outright: rot15 40%→100%.
  • dt (HOG on the distance transform) adds noise robustness but does nothing for rotation.

  • bbox alone is not worth it (slightly hurts noise) — subsumed by canonicalization.
  • crops stay ~0% in every arm: no global descriptor fixes partial queries. That is the ORB/RANSAC stage-2 track.

  • rot15: 36% → 92% top-1 (top-5 40% → 100%) — the headline fix holds at production scale.
  • rot90: 56% → 88%, noise: 68% → 92%, both with 100% top-5.
  • canon_dt top-5 = 100% on every non-partial variant — the right answer is always on screen.
  • Honest trade-off: scale75 top-1 dips 100% → 88% (angle estimation is slightly less stable after downscaling); top-5 stays 100%.
  • Latency: 4 query variants instead of 18 — and the variants are lossless flips/180s, so quality and speed improve together.

4 · Side-findings

  • Index/image drift: some profiles' current processed/ PNGs differ from what was indexed in March (parity cosine 0.75–0.88 for e.g. EG-00012). The rig (drift-free) scores identity at 100%, production at 84% — part of production's identity misses is stale index data, not algorithm weakness. A rebuild fixes this for free.
  • Near-duplicates (judged identical at 10/10, e.g. RP-76251/76252) cap any matcher's measurable top-1. They are catalog reality, not error.

5 · Recommendation

Productionize canon_dt behind a version flag: build elastofirm-index-128-v2.db from current images with canonicalized preprocessing + DT-HOG (one shared preprocess function for index and query), switch via MATCHER_VERSION=v2, keep v1 untouched for instant rollback. Acceptance: re-run elastofirm eval matcher (expect rot15 ≥ 90% top-1, top-5 100% on non-crops), the 31-test regression suite, and a judge spot-check. Then start the ORB/RANSAC stage-2 pilot for the crop 0% — the only remaining failure mode.
