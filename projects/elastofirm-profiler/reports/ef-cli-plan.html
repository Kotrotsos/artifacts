One intuitive, safe command-line tool replacing today's ~20 loose scripts. Subcommand structure (ef <group> <command>), read-only by default, destructive operations gated behind --apply with automatic backups. This is the plan only — nothing is built yet.

2 · Design principles

Safe by default

  • Read-only unless --apply. Every mutating command runs as a dry-run first: it prints exactly what would change (rows, files, sizes) and exits.
  • Auto-backup before destructive writes (ingest, full reindex, restore, vacuum) to ~/backups/<timestamp>/ — refuses to run if backup fails.
  • Typed confirmation for irreversible ops (type 'reindex' to continue), skippable with --yes for automation.
  • Lock file (.ef.lock) so two ingest/index runs can't collide.
  • Protected columns: ingest never drops toepassing/omschrijving, tracking columns, scaffolded datamodel columns, or usage_events/tos_acceptances tables — it merges instead of replacing.

Intuitive & scriptable

  • One entry point: ef <group> <command>; ef alone shows grouped help; every level has -h with examples.
  • ef status as the front door: one screen with DB counts, index coverage, Azure + API connectivity.
  • --json on every command for scripting; meaningful exit codes (0 ok · 1 error · 2 validation · 3 locked).
  • Stdlib only for the CLI core (argparse): no new dependencies; reuses the project's existing pandas/azure/opencv stack via imports.
  • Back-compat: old ef.py --rf … flags keep working for one release, printing the new equivalent (→ use: ef blob find …).

4 · Safety model (summary)

OperationDefaultTo executeBackupConfirm
blob / status / export / eval / db queryruns———
data ingest / import-legacy / index syncdry-run--applyautomaticsummary y/N
index run --deltadry-run (lists delta)--apply—summary y/N
index run --full / db restore / db query --writedry-run--applyautomatictyped word
data pipelineprints full plan--applyautomatictyped word (once)

--yes replaces interactive confirmation for cron/automation — it never skips the backup. A run log (~/.ef/history.log) records every --apply with timestamp, command and backup location.

5 · Architecture & rollout

Structure

cli/
  ef/
    __main__.py     # arg tree, dispatch
    _safety.py      # dry-run, backup, lock,
                    # confirm, history log
    _output.py      # tables, --json, colors
    blob.py  data.py  index.py
    export.py  evalcmd.py  db.py  admin.py
ef            # 2-line launcher: python -m cli.ef
ef.py         # back-compat shim (1 release)

Thin commands; heavy lifting stays in the existing modules (image_search, data/import_csv.py, …) imported as libraries — no logic duplicated.

Phases

  1. Skeleton + safety rails — arg tree, _safety.py, ef status, ef blob *, ef db backup/tables/query
  2. Data path — ef data * (merge-ingest with protected columns), ef export *
  3. Index path — ef index * with delta-by-default + guarded --full
  4. Eval + admin + shim — ef eval *, ef admin *, deprecation forwarding in ef.py, README

Each phase: implement → regression suite → live verify → board/Linear per the established flow.
