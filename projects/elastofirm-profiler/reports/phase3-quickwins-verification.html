▶ INC-78

Role flags: download DXF & see customer

M Verified In Review

Two capabilities derived from Azure AD roles, exposed on /api/auth/me: can_download_dxf (Engineering/Beheer) and can_see_customer (hidden for Sales/CustomerService). Enforced server-side: /api/download-dxf returns 403 without the flag, and the customer name is stripped from /api/profiles, the detail, and image-search responses for restricted roles — while the customer filter keeps working. Frontend hides the DXF affordances; the customer badge auto-hides (it's already guarded on a present value).

Touched: api/main.py (can_download_dxf/can_see_customer, gates + stripping), app/page.tsx (DXF gating)

Verify visually
  1. As a normal dev user (capabilities on) DXF + customer show as before.
  2. Expected (restricted role): no DXF download affordance and a 403 on the endpoint; customer name absent from results/detail but still usable as a filter. Verified in dev via the capability flags + isolated role logic (Sales → dxf false / customer false; Engineering → both true).

Default for unmapped/no-role users is permissive (preserves current behaviour); the full role matrix is INC-81. Confirm the exact Entra app-role strings.

Touched: app/page.tsx (prioritizeArea state, area rerank, toggle, deps/effect)

  2. In the results header, flip Sort by surface (area) similarity.

Note: image-search only. Verified by compile + logic-mirror of the proven weight rerank; full reorder needs a real image upload to confirm (not covered by the API suite).
