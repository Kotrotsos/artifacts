INC-88 In Review

Weight & surface shown in the result list

Result cards (grid and list) now show meter weight in g/m and surface in mm², so a 147 g profile is visually distinct from a 12 kg one. Data was already fetched; it just wasn't surfaced.

Touched: app/page.tsx (grid + list cards, Scale icon)

Verify visually
  1. Open http://localhost:3001.
  2. Click Search Profiles (no filters needed) to list profiles.
  3. Look at any result card in grid view, then toggle to list view.
  4. Expected: each card shows a weight value like 168 g/m and a surface like 1.18 mm² (a dash — when the value is missing). Heavy vs light profiles are now obvious at a glance.
INC-98 In Review

Searching on industry alone now returns results

Previously, selecting only an industry as your first action showed nothing. Root cause was the frontend search trigger (not the backend — the API always returned the rows). A filter change now drives a debounced search that runs with the current filter state.

Touched: app/page.tsx (triggerDebouncedSearch + filter-keyed effect)

Verify visually
  1. Open a fresh http://localhost:3001 (it should read "Please perform a search first…").
  2. In the Industry filter, type Agri and pick it — and do nothing else (do not click Search).
  3. Wait about a second for the auto-search.
  4. Expected: the header reads 159 profiles found and the grid fills — without clicking the Search button.
INC-99 Already fixed + hardened

No "no products found" before the first search

The not-searched vs no-results distinction already existed in the current code. Added a guard so the "No profiles found" message can't flash while a search is in flight.

Touched: app/page.tsx (no-results block gated on !isLoadingProfiles)

Verify visually
  1. Open a fresh http://localhost:3001 (or hard-refresh).
  2. Do not search yet — just look at the results panel.
  3. Expected: it shows "Please perform a search first…", never "No profiles found". The no-results message only appears after a search that genuinely returns zero rows.
