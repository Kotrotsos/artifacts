▶ INC-93

Filter on process (LCM / autoclaaf)

S Planned

Validated finding: every other filter (compound, industry, customer, mold, department, primary line) comma-splits for multi-select, but process_type is a single exact match (api/main.py:950 and :1200) — so selecting LCM and autoclaaf matches neither.

Planned approach: add the same comma-split OR logic to process_type in both /api/profiles and /api/profiles/count, and dedupe the case variants (AUTOCLAAF vs autoclaaf) in /api/filters.

▶ INC-89

Sort similarity by surface instead of weight

M Planned

Validated finding: a prioritizeWeight rerank already exists as a working template (app/page.tsx:759, :1622), but there is no area equivalent. Surface is the geometry-true measure (weight shifts with compound density).

Planned approach: add a prioritizeArea toggle and parseArea helper that re-sorts results by absolute distance to the top result's surface; mutually exclusive with the weight toggle.

▶ INC-85

Filter button "incomplete data records"

M Planned

Validated finding: no incomplete-data filter exists yet, and the runtime schema already exposes the fields needed (Area, [Metergewicht tekening], Compoundcode, hardness, SG, image_extension).

Planned approach: add an incomplete_data param to /api/profiles + count that selects rows with any required field NULL/empty/sentinel, a toggle in the filter panel, and wire it into the Excel export. Replaces the manual lists the PO sends to Simon.

▶ INC-88

Weight & surface shown in the result list

Verified In Review

Result cards (grid and list) now show meter weight in g/m and surface in mm², so a 147 g profile is visually distinct from a 12 kg one. Data was already fetched; it just wasn't surfaced.

Touched: app/page.tsx (grid + list cards, Scale icon)

Verify visually
  1. Open http://localhost:3001.
  2. Click Search Profiles (no filters needed) to list profiles.
  3. Look at any result card in grid view, then toggle to list view.
  4. Expected: each card shows a weight like 168 g/m and a surface like 1.18 mm² (a dash — when missing). Heavy vs light profiles are obvious at a glance.
▶ INC-98

Searching on industry alone now returns results

Verified In Review

Previously, selecting only an industry as your first action showed nothing. Root cause was the frontend search trigger (not the backend — the API always returned the rows). A filter change now drives a debounced search that runs with the current filter state.

Touched: app/page.tsx (triggerDebouncedSearch + filter-keyed effect)

Verify visually
  1. Open a fresh http://localhost:3001 (reads "Please perform a search first…").
  2. In the Industry filter, type Agri and pick it — do nothing else (do not click Search).
  3. Wait about a second for the auto-search.
  4. Expected: the header reads 159 profiles found and the grid fills — without clicking Search.
▶ INC-99

No "no products found" before the first search

Verified In Review

The not-searched vs no-results distinction already existed in the current code. Added a guard so the "No profiles found" message can't flash while a search is in flight.

Touched: app/page.tsx (no-results block gated on !isLoadingProfiles)

Verify visually

  3. Expected: it shows "Please perform a search first…", never "No profiles found". The no-results message only appears after a search that genuinely returns zero rows.
