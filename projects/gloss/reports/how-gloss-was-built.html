Project recap, Gloss

How we built an AI driven blog

Gloss is a Flask blog where the brand was extracted by AI, the articles are written and published by AI through an API, and the reader experience is layered with AI assistance. The whole thing was built in roughly 24 days, from initial scaffold on 6 March to the last polish on 30 March.

The stack at a glance

Server Flask 3, gunicorn, Python 3.12
Storage PostgreSQL (started on SQLite)
Markdown markdown-it-py + mdit plugins + Pygments
AI OpenAI gpt-4o-mini, later gpt-5.2
Auth Magic links via Resend, email allowlist
Hosting Railway, Nixpacks
Safety nh3 HTML sanitizer
Perf flask-compress, Pillow WebP

The brand came first, then the code

Before any feature work, the visual DNA was captured in dna.md. It pinned down a Cohere-leaning premium-editorial direction: warm off-white background #f2f1ef, deep forest green as the primary action color, coral as the accent, almost no blue. DM Serif Display for headings, DM Sans for body, DM Mono for labels. Organic blob shapes on cards, soft pills, unhurried motion. Everything that followed inherits from that file.

The build, phase by phase

Phase 1, 6 to 7 March, foundation

Scaffold, dashboard, deploy

  • Initial Flask scaffold with markdown-it-py, SQLite, OpenAI client, slugify, Pillow.
  • Post management dashboard and image manager under /manage.
  • Railway deploy config, Procfile, Nixpacks, gunicorn.
  • Magic link auth via Resend so non-developers can sign in.
Phase 2, 9 March, the AI publishing pipeline

An API for agents, not just humans

  • Public API v1 for programmatic publishing, the core piece that lets AI agents draft and ship posts without touching the editor.
  • Hero image auto-extracted from the first image in markdown.
  • SQLite moved into the persistent volume, then migrated to PostgreSQL with an admin email allowlist.
  • Markdown linkify, then tightened to only auto-link explicit protocol URLs.
  • Connection pooling, helper extraction, Google Analytics.
Phase 2b, 9 March, AI-native reader plumbing

Make the blog legible to other AIs

  • /llms.txt and /llms-full.txt endpoints, auto-generated, so other agents can index the site cleanly.
  • Pygments syntax highlighting and per-block copy buttons.
  • Image lightbox with double-tap, dark mode tuned for WCAG contrast.
  • Google AdSense with non-intrusive placement, ads.txt.
  • Top-5 tag filter bar, floating edit button for admins on each post.
Phase 3, 9 to 10 March, AI inside the reader

Suggested articles, multiple authors, chat-with-article

  • AI-suggested articles sidebar on each post.
  • Multiple authors with random assignment, so the byline reads like a real publication.
  • Chat-with-article, a floating bubble that lets readers ask questions of the current piece, with an animated typing indicator.
  • Security hardening pass across the app, nh3 fix for sanitized HTML.
  • Card-type system with four preview variants, zoom control in the nav.
Phase 4, 11 to 16 March, content strategy

Let the data choose what gets featured

  • Engagement tracking, an engagement API endpoint for content strategy.
  • Auto-featured articles selected from engagement signals instead of manual curation.
  • Homepage redesigned in a Wired-style magazine layout.
  • More Stories grouped by topic, requires 2+ articles, sorted by count.
Phase 5, 20 to 21 March, Gloss Insights

Per-article AI takeaways

  • Model upgraded from gpt-4o-mini to gpt-5.2.
  • Gloss Insights, AI-generated takeaways and a practical-actions paragraph attached to every post.
  • Working through the GPT-5.2 API change, max_tokens became max_completion_tokens.
  • Images stripped from insight input, markdown fences stripped from output.
  • Admin endpoint to clear cached insights when prompts change.
Phase 6, 21 to 30 March, ship polish

SEO, speed, and the chat pill

  • Full SEO meta: Open Graph, Twitter Card, JSON-LD, canonical URLs.
  • Auto WebP conversion, gzip via flask-compress, lazy loading, font preloading, preconnect hints, long-cache headers.
  • Chat restyled as a pill with a label, aligned with the edit button, both anchored bottom-right.

What makes it “AI driven” in practice

  • authoring Articles drafted by an external agent and pushed through /api/posts, the same way a human would publish but at agent cadence.
  • editor AI Inside the editor, endpoints for title, tags, excerpt, generate, improve, all wired to ai_complete() in app.py.
  • reader AI Suggested articles, Gloss Insights, and chat-with-article, all live on the post page.
  • agent-friendly /llms.txt and /llms-full.txt so other AIs can consume Gloss as a clean source.
  • data-driven Engagement signals choose what gets featured, not the admin.

The shape of the codebase

  • app.py, single Flask app, all routes, AI endpoints, markdown rendering, helpers.
  • templates/, base, index, post, editor, manage, images, login.
  • static/style.css, the design system from dna.md.
  • uploads/, image volume that also hosts the DB on Railway.
  • dna.md, the brand brief that every visual decision traces back to.
